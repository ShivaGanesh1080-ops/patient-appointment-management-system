ABSTRACT

Modern healthcare institutions and outpatient clinics face significant operational hurdles caused by manual, fragmented, or paper-based appointment scheduling. These legacy processes cause prolonged patient wait times, uncoordinated clinic lines, lack of doctor transparency, and severe scheduling conflicts such as double-booking.

This project develops MediPulse (Patient Appointment Management System), a robust full-stack web and mobile application engineered strictly according to the Web Technologies and Mobile Programming (WTMP) syllabus. Built using HTML5, CSS3, Tailwind CSS, ES6+ JavaScript, Node.js, Express.js, and an ACID-compliant SQLite relational database, the platform implements:

  • Doctor Profiles & Taxonomy: Comprehensive physician profiles detailing qualifications, specialties, consultation fees, ratings, and active clinic days.
  • Dynamic Time-Slot Scheduling: Algorithms evaluating weekly working schedules to generate 30-minute intervals marked as Available, Booked, or Past in real time.
  • Atomic Booking & Race Condition Prevention: Enforces dual-level concurrency checks to reject simultaneous double-booking with HTTP 409 Conflict.
  • Cancellation Audit Logs: Mandatory medical reason capture that frees reserved slots immediately back into the pool.
  • Appointment History & Tracking: Real-time lookup by mobile phone or booking reference token.
  • Doctor Operations Desk: Live patient queue management for physicians to complete visits and track clinic revenue.
  • Printable Consultation Pass: Thermal/PDF-ready physical passes with QR token verification.

KEYWORDS: Patient Appointment Management, Full-Stack Web Development, Node.js, Express.js, REST API, SQLite, Concurrency Control, Race Condition Prevention, Semantic HTML5, CSS3, Tailwind CSS, Mobile-First Design, Web Technologies, HealthTech.

2. INTRODUCTION

In clinical healthcare management, outpatient consultation scheduling plays a decisive role in patient satisfaction and clinic productivity. Traditional approaches depend on telephonic inquiries, walk-in paper tokens, or disconnected software tools. This project develops MediPulse, an integrated clinical appointment management system designed to eliminate queue congestion, ensure transparent doctor profiles, and prevent scheduling collisions through transactional consistency.

3. PROBLEM STATEMENT

Conventional hospital scheduling workflows suffer from key pain points:

  • Queue Congestion: Patients arrive unannounced, causing crowded waiting rooms and erratic physician schedules.
  • Double-Booking Race Conditions: Receptionists scheduling simultaneously often assign two patients to the identical consultation slot.
  • Opaque Credentials & Fees: Patients lack advance access to doctor qualifications, consultation fees, and working hours.
  • Lack of Cancellation Recirculation: Cancelled visits are rarely logged in time, wasting precious clinical consultation windows.

4. REQUIREMENT ANALYSIS

4.1 Functional Requirements

  • FR1 (Doctor Profiles): Render doctor directory with credentials, ratings, experience, consultation fees, and working days.
  • FR2 (Dynamic Slots): Generate dynamic 30-minute intervals categorized by Morning, Afternoon, and Evening sessions.
  • FR3 (Atomic Booking): Validate 10-digit mobile number, patient age, gender, and clinical symptoms, issuing a unique token (APT-2026-XXXX).
  • FR4 (Concurrency Guard): Prevent double-booking by returning HTTP 409 Conflict if a slot was already reserved.
  • FR5 (Cancellation Management): Cancel appointments with mandatory audit reasons, immediately freeing slots.
  • FR6 (Doctor Portal): Enable physicians to manage their queue and mark consultations as "Completed".

4.2 Non-Functional Requirements

  • Performance: Sub-50ms API response time under concurrent clinical intranet workloads.
  • Data Integrity: Full ACID transaction compliance via SQLite Write-Ahead Logging (WAL mode).
  • Security: Parameterized SQL prepared statements to prevent SQL Injection (SQLi).
  • Responsiveness: Mobile-first UI conforming to WTMP mobile programming standards.

6. DATABASE DESIGN

The system stores structured clinical data across three normalized relational tables:

Table Name Primary Key Foreign Keys Key Attributes
departments id None name (UNIQUE), icon, description
doctors id department_id name, qualification, experience_years, consultation_fee, rating, clinic_address, available_days, slot_start_time, slot_end_time
appointments id (AUTO) doctor_id booking_reference (UNIQUE), patient_name, patient_phone, patient_age, patient_gender, appointment_date, appointment_time, reason, status, cancellation_reason

Indexes Configured: idx_appointments_doctor_date (doctor_id, appointment_date, appointment_time, status) and idx_appointments_phone (patient_phone) for rapid conflict detection.
